### Update List

- We split the mic button into two modes: **ASK** (auto-stops recording on silence, same as previous TALK behavior) and **TALK** (stays on until manually stopped, for continuous conversation). The button row is now [ASK][TALK] on the left half and [SEND] on the right half. Both buttons show "STOP" when active, and clicking one while the other is active stops the first session before starting the new one. TALK mode uses the same Deepgram STT flow as ASK but passes no silence callback, so the mic stays hot. Future enhancement: local VAD gating in TALK mode to avoid sending silence to Deepgram (see TODO.md).
- We drafted a document outlining the preset format/schema, based on the Vital codebase and some example presets: `agents/vital-assistant/PRESET_SCHEMA.md`
    - We learned that waveforms can be stored as "Wave Source" (base64, not really LLM-friendly) OR "Line Source" (control points / curves, very LLM-friendly). We will prefer line source for preset generation. We will deal with wave source later.
- We created a build script `build_macos.sh` because we are developing on MacOS. This runs Projucer CLI to build the project to MacOS (Xcode) and other targets. Then it uses Xcode CLI to run the debug app. We can use this script with `--no-run` argument to verify that new changes build/compile successfully.
- We added a sidepanel (via `side_panel.cpp`) where we will continue to add functionality
- We added a textarea and a button to the sidepanel, near the bottom
- We implemented a chat interface with scrollable message area, user message bubbles, and "Thinking..." indicator
- We added a menu option to save claude API key path in user settings (Vital json config stored in `Library/Application Support` or `APPDATA`, etc.) and load the path when the app starts
- We added an API client for Claude (Anthropic/Claude Platform API). The side panel initializes the API client with the API key (if exists), checks internet access, and adds a "Ready" message to the chat window.
- We implemented chat message sending to Claude API with background threading: user submits message -> sidepanel notifies listeners -> `FullInterface::sidePanelMessageSubmitted()` calls `ClaudeApiClient::sendMessage()` -> background thread makes HTTP POST -> response delivered via `MessageManager::callAsync()` back to UI thread
- We added persistent conversation history (max 20 messages) to ClaudeApiClient: each new message is added to history, the API sends full conversation context, and responses are stored for multi-turn dialogue
- We added a system prompt for the Vital AI assistant: `ClaudeApiClient` loads `SYSTEM_PROMPT.md` from the app bundle Resources dir (fallback to data dir), sent via the Anthropic API's top-level `"system"` field. The build script copies the prompt file into the bundle.
- We added current preset JSON injection to Claude API chat: when user sends a message, the synth preset is serialized to JSON and injected as a user message before the actual message. Base64 data (wave_data, samples) is stripped to save tokens.
- We switched from full preset JSON responses to a JSON diff/merge patch approach (RFC 7396 style): Claude returns only changed keys, which are recursively merged into the current preset via `mergeJson()`. This avoids token limits (full presets are 4000+ lines). Added `loadStateFromJson()` public wrapper on `SynthBase` to apply the merged result.
- We added cost control limits: API output tokens capped at 1024 (`kMaxTokens`), and user input messages truncated to 1024 characters before being added to conversation history (preset JSON context is not truncated).
- We added preset schema loading to ClaudeApiClient: `PRESET_SCHEMA.md` (documenting all parameters, value ranges, and scaling formulas like quadratic/exponential) is loaded at init and appended to the system prompt. This gives the AI assistant accurate knowledge of how to compute stored values from user-facing percentages (e.g., quadratic: stored = sqrt(UI_value)).
- We added markdown rendering for chat messages: vendored md4c (C markdown parser, MIT) in `third_party/md4c/`, created `markdown_parser.h/cpp` that parses markdown into `MarkdownBlock`/`StyledRun` structs via SAX callbacks, and updated `side_panel.cpp` to render paragraphs with bold/italic/mono, headings, fenced code blocks, bullet/numbered lists, block quotes, and horizontal rules. System messages are parsed as markdown; user messages stay plain text.
- We improved API response handling to support mixed text+JSON responses: the response parser extracts JSON from markdown code fences (``` blocks, including ` ```json ` indicators), applies preset diffs from the JSON, and displays surrounding text (before/after the fence) as a chat message. This allows the AI to explain changes alongside applying them. Added random whimsical completion phrases (`getCompletionPhrase()`) as fallback when no text accompanies a preset update. The extraction logic properly handles cases where the model returns both a message and a JSON update in a single response.
- We improved `mergeJson()` to handle wavetable arrays intelligently: array elements are now merged element-by-element (null means keep original), and placeholder strings like "(base64 data removed)" are skipped so the AI can't accidentally overwrite real base64 data with stripped placeholders.
- We implemented Anthropic API prompt caching in `ClaudeApiClient`: the system prompt (including preset schema) is sent as a cacheable content block with 1-hour ephemeral TTL and extended cache header. This reduces subsequent request input token costs by ~90% on the cached portion (~99% of costs were input tokens before).
- We fixed placeholder text wrapping in multiline `OpenGlTextEditor`: overrode `paintOverChildren()` to calculate word wrapping at paint time, added `wrapText()` helper and stored placeholder text/color locally (JUCE's members are private). Root cause was JUCE's `TextEditor::paintOverChildren()` hardcoding ellipsis.
- We added voice-to-text input via Deepgram STT: a MIC toggle button in the side panel starts/stops microphone recording, streams audio over WebSocket to Deepgram's Nova-3 API for real-time transcription, shows interim transcripts as a live preview in the text editor, and auto-submits final transcripts as chat messages. Created `DeepgramClient` (singleton, PIMPL pattern) for WebSocket STT, `MicrophoneCapture` for isolated mic recording with 16kHz resampling, and `mic_permission_mac.mm` for macOS permission handling. Vendored IXWebSocket library for WebSocket+TLS support. Deepgram API key uses the same file-path-in-config pattern as the Claude API key.
- We renamed the dual voice buttons from ASK/TALK to **VOICE CHAT** / **TALK** with new layout: [VOICE CHAT (half-width)] [TALK (quarter)] [SEND (quarter)]. VOICE CHAT is always-on mode with a hardcoded 20s silence timeout and shows a popup warning on start. TALK auto-stops on configurable silence timeout (default 2.5s). Added `silence_timeout_override` parameter to `MicrophoneCapture::startCapture()` so each mode can specify its own timeout. Commented out the silence timeout config menu for now.
- We added a **clear/reset button** (x icon) to the top-right of the chat side panel, in the same row as the "SOUND DESIGNER" title. Clicking it resets the chat UI to its starting state: clears all messages, stops active recording, clears the text editor, resets the API conversation history via `ClaudeApiClient::clearConversation()`, and shows the initial "Ready to create!" message. Added `clearConversation()` public method to `ClaudeApiClient`.
- We fixed a **cross-platform bug** where the AI chat feature worked on macOS but not on Windows. The system prompt and preset schema files were not being found on Windows because `ClaudeApiClient` only searched the macOS bundle path and user data dir, but `build_windows.bat` places them next to the `.exe`. Added the exe-adjacent directory as a search path in `loadSystemPrompt()` and `loadPresetSchema()`.
- We fixed a **Windows Voice Chat crash** caused by ixwebsocket having no TLS backend on Windows. The build had `IXWEBSOCKET_USE_SECURE_TRANSPORT=1` (Apple-only); on Windows, TLS socket creation returned null, crashing on dereference when connecting to Deepgram's `wss://` endpoint. Integrated mbedTLS 3.6.5 as the Windows TLS backend (`third_party/mbedtls/`), moved platform TLS defines to per-exporter `extraDefs` in `vital.jucer`, added `ix::initNetSystem()`/`ix::uninitNetSystem()` calls in `DeepgramClient`, and linked `crypt32.lib`+`bcrypt.lib`. Used forward declarations instead of `#include "IXNetSystem.h"` to avoid unity build Windows header pollution (`min`/`max` macro conflicts).
- We added a **global keyboard shortcut Cmd+K (macOS) / Ctrl+K (Windows/Linux)** to focus the chat prompt editor from anywhere in the UI. Implemented via `FullInterface::keyPressed()` override that catches unhandled Cmd+K events and delegates to `SidePanel::focusPromptEditor()`, which calls `grabKeyboardFocus()` on the `OpenGlTextEditor`.
- We fixed **conversation history context pollution** in `ClaudeApiClient`: preset JSON was being stored in `conversation_history_` every turn (stale snapshots wasting tokens), and assistant responses with JSON fences were stored verbatim. Now preset context is injected ephemerally per-API-call only, and assistant JSON is stripped before storing in history. Extracted shared `ClaudeApiClient::extractFenceContent()` utility from inline logic in `full_interface.cpp`.
- We implemented **autosave checkpoints and chat restore**: every sent/received message triggers an autosave of the current preset to `<data_dir>/autosaves/checkpoint_<timestamp>.vital`. Hovering over a user message shows a restore button (return arrow icon) in the top-right corner. Clicking it opens a native `AlertWindow` confirmation dialog; on confirm, the autosaved preset is loaded, chat messages after that point are removed from the UI, and API conversation history is truncated via `ClaudeApiClient::truncateHistoryTo()`. Restore on a user message maps to the next system message's checkpoint (state after AI applied changes). On "CLEAR", checkpoints are archived to a named folder (first 7 words of first user message); on startup, orphaned checkpoints from crashes are archived to `unsaved_session/`. Caps: 50 checkpoints per session, 20 archived sessions. Fixed an MSVC compile error where `vector::resize()` required a default constructor on `ChatMessage` -- switched to `vector::erase()` instead.
- We redesigned the restore button to use an instant **edit mode** pattern (Claude web UI style, no confirmation dialog): clicking the restore button removes the user message and all subsequent messages, restores the message text to the input editor for editing, and shows a cancel (X) button. User can then edit and re-submit, or press ESC / click the cancel button to undo the edit and restore all messages and synth state from snapshot. `EditModeSnapshot` struct saves full messages list, checkpoints, API history size, and synth state for complete rollback. Implementation added to `side_panel.h/cpp` with edit mode state machine, keyboard handler for ESC, and modified message submission flow; listener methods added to `full_interface.h/cpp` to support checkpoint saving and API history tracking.
- We implemented a **multi-layer agentic chat flow** with a router layer that analyzes user messages before sending to preset generation. Router uses Claude tool_use to decide: single-action requests pass through transparently, multi-action requests are split and executed sequentially with status updates ("Breaking it down..." → "Step 1/N..." → etc). Each sub-action sees the updated preset state from previous steps. Router system prompt is tuned to minimize splitting (batch simple independent changes). Added `routeMessage()` and `addToHistory()` to `ClaudeApiClient`, added `routeAndExecute()` and `executeNextAction()` orchestration methods to `FullInterface`, added `updateStatusMessage()` to `VitalSidePanel` for in-place status updates. Fixed two bugs: (1) updateStatusMessage() wasn't visually updating because ChatMessage stores parsed markdown blocks separately from text, (2) clearThinkingMessage() only matched "Thinking..." exactly so step messages weren't cleaned up; (3) system message padding was too large. Complex sound design requests return sentinel "THIS REQUIRES COMPLEX SOUND DESIGN" (TBD handling).
- We fixed a **critical bug in checkpoint/restore edit mode** where subsequent restores silently failed after the first restore+cancel cycle. Root cause: `removeCheckpointsAfter()` deleted checkpoint `.vital` files from disk during restore, but `cancelEditMode()` restored stale checkpoint objects whose files no longer existed, causing `autosave_file.exists()` to return false on future restores. Fix: added `delete_files` parameter to `removeCheckpointsAfter()` (false during restore to preserve files for cancel), extracted `exitEditMode()` helper that diffs snapshot vs current checkpoints and only deletes orphaned files, fixed `clearChat()` not resetting `edit_mode_`, fixed `processRecordedSpeech()` not clearing edit mode, and made `sidePanelRestoreRequested` return bool so `enterEditMode` checks success before committing.
- We implemented a **sound design translation layer** as the third path in the multi-layer agentic router. Non-technical descriptions like "blippy jangly synth lead" or "warm analog pad" are detected by the router via a `sound_design_required` boolean in the tool schema. When triggered, a separate Claude call translates the description into numbered technical parameter instructions using `SOUND_DESIGN_PROMPT.md` and `SOUND_DESIGN_GUIDE.md`. The translation is NOT shown in chat and NOT stored in conversation history (internal intermediate step). The translated instructions are then re-routed through the router for splitting and sequential execution. An `is_sound_design_reroute_` flag prevents infinite re-routing loops. Also fixed JSON truncation bug by increasing `kMaxTokens` from 1024 to 4096 for preset generation calls. Added `saveChatLog()` debug method to `VitalSidePanel` for writing chat messages to disk.
- We reduced API token costs and eliminated conversation history pollution through 6 incremental improvements: (1) Fixed JSON leaking into assistant history by detecting code fences and storing `"(preset updated)"` placeholder instead of full JSON response. (2) Added `cleanupSubActionHistory()` to remove ephemeral sub-action prompts and placeholders after multi-action flows complete. (3) Stored original user message before sound design reroute to preserve the original request. (4) Switched router model from Opus to Sonnet, reducing input token costs by 60x since router only outputs ~50-100 tokens. (5) Renamed all cookbook file references from `SYNTHESIZER_COOKBOOK.md` to `SOUND_DESIGN_GUIDE.md` (file was already renamed, code references were stale). (6) Added request/response logging via `logRequest()` method that records timestamp, endpoint label, request/response sizes, token usage (input, output, cache read, cache create), and full bodies to `api_requests.log` in data directory for cost analysis.
- We conducted a research and analysis session on API token costs by auditing request logs from Feb 21, 2026. Identified 3 request tiers (~90-95k tokens for sound design, ~27-32k for standard preset mods, ~1-5k for router), mapped the full request flow, audited all history write-points in the codebase (3 call sites to `addMessage()`), and identified 5 bugs causing history pollution and cost inflation. Created a detailed implementation plan at `.plans/harmonic-questing-bird.md` covering Changes 1-5 with exact file locations, code diffs, and verification steps. Total daily cost was ~$14.92 with $10.27 from uncached input tokens as the dominant factor.
- We fixed two critical bugs discovered during token cost reduction testing: (1) **Invalid Sonnet model ID**: `kModelSonnet` constant had a fabricated date `claude-sonnet-4-5-20241022` that never existed. Fixed to `claude-sonnet-4-5-20250929`. This was never caught because Sonnet wasn't used until we switched the router to it. (2) **Multi-action one-shotting**: When multi-action flows ran, the LLM saw the full original user message (or sound design translation text) in conversation history alongside the first sub-action, causing it to complete all steps at once on the first request, making subsequent sub-actions return only "already done" text (token waste). Fixed by removing the intermediate `addToHistory("user", message)` call that stored the full original message before sub-actions execute, and eliminating the `cleanupSubActionHistory()` post-completion cleanup since sub-actions now stay in history permanently as an accurate record. Sound design multi-action history now contains: original message + sub-action 1 + response + sub-action 2 + response (no translation text). Non-sound-design: sub-action 1 + response + sub-action 2 + response (no original multi-part message).
- We enhanced `splitResponseText()` in `ClaudeApiClient` to handle all 3 JSON response formats from the LLM (renamed from `extractFenceContent()`): pure JSON without fences, text + JSON with fences, and text + JSON without fences. Added detection for responses starting with `{` and inline JSON detection via `{"settings"` substring. This fixed conversation history pollution where raw JSON was leaking into chat, and a display bug where JSON without fences was shown verbatim to the user. No changes needed at call sites — downstream consumers already handled the textOut/jsonOut split correctly. Updated declarations and call sites in `claude_api_client.h/cpp` and `full_interface.cpp`.
- We fixed a bug where stale API responses could corrupt the chat UI after an edit-mode restore. When a user clicks "restore" while an API request is in flight, the async callback would still fire and add messages to the truncated UI. Added a generation counter (`api_request_generation_`) to `FullInterface` that is bumped on restore and cancel-edit; async callbacks capture and check the generation, silently discarding stale responses.
- We externalized the router system prompt from a hardcoded C++ constant into `prompts/system_prompts/ROUTER_PROMPT.md`, loaded at runtime like other prompts. Added a compact "VITAL TECHNICAL TERMS" parameter reference to help the router accurately distinguish technical vs non-technical requests. Moved all prompt files from `agents/vital-assistant/` to `prompts/system_prompts/` and updated all 3 build scripts accordingly.
- We replaced the SPEAK/TALK button in the side panel's bottom button row with a **microphone icon overlay** on the textarea. The button row is now simplified to [VOICE CHAT | SEND] (was [VOICE CHAT | TALK | SEND]). The mic icon sits at the bottom-left of the textarea as a `PlainShapeComponent` (SVG-based, OpenGL-rendered) and toggles talk recording on click. Mouse events are forwarded from the text editor via `addMouseListener()`. Also reduced voice chat silence timeout from 20s to 15s.
- We fixed a bug where pressing **clear conversation** while an API response was in-flight would still deliver the stale response to the cleared chat. Added `sidePanelClearRequested()` listener callback so `clearChat()` bumps the `api_request_generation_` counter (same invalidation pattern already used by restore and cancel-edit).
- We fixed **queued message handling during multi-action processing**: `updateStatusMessage()` and `clearThinkingMessage()` now scan backwards to find target messages past interleaved user messages; moved "Thinking..." indicator creation from `submitMessage()` to `sidePanelMessageSubmitted()` so it's only added when actually processing (not when queuing); fixed all 3 queue processing points dropping messages beyond the first by dequeuing one at a time instead of `swapWith`.
- We **re-architected the side panel UI buttons** into inline textarea controls. Removed the VOICE CHAT and SEND button row below the textarea; extended the textarea to the bottom of the panel. Added a dual-purpose circular action button (bottom-right, purple circle background) that shows mic icon (empty textarea → start talk), send arrow icon (has text → send), or stop icon (recording → stop) via a 3-state machine (`ActionButtonMode` enum + `updateActionButtonState()`). Moved the VOICE CHAT button inside the textarea (bottom-left, smaller inline). Added `sendArrowIcon()` and `stopIcon()` SVG paths to `paths.h`. Fixed rendering issues where programmatic stroked paths appeared as black boxes by switching to SVG path data.
